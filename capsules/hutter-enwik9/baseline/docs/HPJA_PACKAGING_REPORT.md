## 1. What the Hutter Prize Judging Assistant (HPJA) requires — verified facts

Source: https://github.com/jabowery/HutterPrizeJudgingAssistant, cloned at commit
`4c3deb2fdcf458b025d9c41581d8c598d4a75ecc` (Tue Sep 22 17:45:58 2026 -0500). File references below
are to that commit; the harness is alpha and changes often, so re-check before submitting.

Entry directory ([ENTRANT_INSTRUCTIONS.md §1–2](https://github.com/jabowery/HutterPrizeJudgingAssistant/blob/main/ENTRANT_INSTRUCTIONS.md)):
`entry.env` + the submitted archive + ONE source tar/zip. `entry.env` is parsed as data, `KEY=VALUE` per
line, `#` comments allowed, closed key whitelist (`lib/entry-env.sh:78-95`: ENTRY_FORMAT, EXECUTION_PLATFORM,
QUALIFICATION_OS, SOURCE_PACKAGE, COMPRESSOR, COMPRESSOR_FORMAT, COMPRESSOR_ARGUMENTS, ARCHIVE, ARCHIVE_FORMAT,
DECOMPRESSED_OUTPUT, DECOMPRESSOR*); any other key rejects the entry. Values naming files are basenames of
`[A-Za-z0-9._-]`. **QUALIFICATION_OS is now mandatory** (`lib/entry-env.sh:104` "missing QUALIFICATION_OS";
zmix 1.0's published `entry.env` omits it — at this commit it would be rejected; older commits defaulted to
ubuntu-22.04). Accepted: `ubuntu-20.04`, `ubuntu-22.04`, `ubuntu-24.04`, each mapped to a digest-pinned image
(`lib/qualification-os.sh`: ubuntu-24.04 → `ubuntu:24.04@sha256:b3cc40b7…3ae15`, ubuntu-22.04 →
`ubuntu:22.04@sha256:58b87898…4e3fe`).

`*_FORMAT` (`ENTRANT_INSTRUCTIONS.md §2`, `docker/validate-executable`): `executable`, `upx` (pure UPX file),
`upx-overlay` (UPX-packed ELF prefix followed by appended data), `data` (archives of the separate-decompressor form
only). `upx`/`upx-overlay` are validated with the repository-pinned **UPX 5.1.1** (`UPX-5.1.1-amd64_linux.tar.xz`,
sha256 `1ff660454227861e00772f743f66b900072116b9dc24f6ee28b97cce88a7828a`, `Dockerfile` → `/opt/upx`): for
`upx-overlay` the validator scans for `UPX!` magics, takes `offset+36` as candidate prefix end and accepts the first
prefix that passes `upx --test`; the byte-identical original is what gets executed and scored.

Source package (`§3`, `docker/prepare-entry`): exactly one top-level directory containing `install.sh`, `build.sh`,
the argument file(s) and the complete source; **no symlinks** (rejected), only dirs/regular files; extracted with
`bsdtar`, the top directory's contents become `/entry` (so `/entry/build.sh`, `/entry/makefile`, …). Do not put
`entry.env` or the archive in it. The package size is **not scored**.

`install.sh` (`§4`, `docker/EntryDependencies.Dockerfile`, `lib/dependency-image.sh`): the only root + network phase,
COPYed alone into a docker build context (`.dockerignore` = `*` + `!install.sh`) → **it sees no source tree**, may only
install dependencies, must be noninteractive/repeatable (retried up to 3×). Runs as root (plain `apt-get`, no sudo).
Loader-visible libraries from `/lib`, `/lib64`, `/usr/lib`, `/usr/local/lib` are copied into a sanitized runtime image;
the base image already carries libc/libm/libstdc++/libgcc_s.

`build.sh` (`§5`, `build-compressor.sh:~150-175`): offline (`--network none`), `--read-only` rootfs, `--user
65532:65532`, `--cap-drop ALL`, `--memory 16 GiB` no swap, `--pids-limit 16384`, source bind-mounted read-only at
`/entry`, cwd `/work` (the only writable mount; `/work/run/tmp` exists mode 1777 and the image's `/tmp` symlinks to it),
HOME unset. It must create the file named by `COMPRESSOR` **in /work**; only that file is copied out.

Argument vector (`§6`): one literal argument per LF-terminated line, no shell; the file's byte count is recorded and
**added to S**.

Runtime (`§7`, `RELAXATION.md`): each invocation is a fresh offline container, cwd contains only the executable, its
argument file and its declared input; UID 65532, no capabilities, Landlock-restricted to cwd/procfs/loader libs/`/bin/sh`.
Default policy `process-tree` (the declared program and descendants may exec programs unpacked from the counted inputs
— UPX self-unpack is fine); `strict` is a diagnostic override. The archive gets **no arguments** and must create
`DECOMPRESSED_OUTPUT`. Limits (`lib/prize-limits.sh`, `qualify-archive.sh`): 16 GiB RAM no swap, peak RSS ≤ 10 GiB,
disk ≤ 100 GB, wall-time limit `int(70000*3600 / GeekbenchScore)` s (`qualify-archive.sh:396`), i.e. 70,000/T hours.

Score (`README.md` "The proposed standard score", `judging_assistance.sh:700`):
`S = bytes(rebuilt COMPRESSOR) + bytes(ARCHIVE generated by that rebuilt compressor) + bytes(COMPRESSOR_ARGUMENTS)`.
The compressor is **rebuilt by the harness and that binary is scored**; the archive it produces is compared with the
submitted one (`archives_identical`), and if they differ the generated archive is decompressed a second time and its
size is what enters S. A rebuild that differs from the submission is therefore not a failure, but every byte the
judge's toolchain adds is charged (twice, for a self-extracting entry whose archive embeds the decompressor stub).

zmix 1.0 (LTCB page http://mattmahoney.net/dc/text.html, links to https://zmix.frostbyrne.io/v1.0/{entry.env,
zmix-src.tar.gz,comp9,archive9.exe,README.md,writeup.md}): its manifest is `ENTRY_FORMAT=self-extracting`,
`COMPRESSOR=comp9`, `COMPRESSOR_FORMAT=upx-overlay`, `ARCHIVE=archive9.exe`, `ARCHIVE_FORMAT=upx-overlay`,
`DECOMPRESSED_OUTPUT=data9`, no QUALIFICATION_OS; its 13.1 MB source tar has one top dir `zmix-src/` with
`install.sh` (apt gcc/g++/make…, builds binutils 2.42, stages zig 0.15.1 + upx 5.2.0 source tarballs under
`/opt/toolchain-src`) and `build.sh` (copies `/entry` to `/work/src`, sets HOME/TMPDIR under /work, builds the
toolchain offline, warns — does not fail — when the rebuild is not byte-identical to its artifact of record). Its
`install.sh` header quotes the judge rejecting build scripts that `sudo apt-get` (unverified: Google-Group thread
"Tightening up compression program build script requirements").

### Consequences for our entry (found while packaging)

- **The compressor must be invoked as `cmix`, the archive as `archive9`.** `src/readalike_prepr/self_extract.h`
  `OpenSelf("cmix")` / `OpenSelf("archive9")`: each program opens *itself by literal name in the cwd* to read the
  appended dictionary/order/weights. A `COMPRESSOR=comp9` declaration would fail with "cmix error: cannot open 'cmix'".
  Hence `entry.env` declares `COMPRESSOR=cmix`, `ARCHIVE=archive9`, and `DECOMPRESSED_OUTPUT=enwik9_uncompressed`
  (the name the argument-less decompression writes, `src/runner.cpp:1059`).
- `-e` takes exactly two arguments (`runner.cpp:990`): input and the intermediate cmix-stream file; `archive9` is always
  written under that fixed name. `comp9.args` = `-e`, `enwik9`, `o` → **12 bytes** charged to S (`archive9` as third
  argument, as the earlier note suggested, would cost 19 and make the intermediate file overwrite/alias the archive).
- Both artifacts are `upx-overlay`: `UPX!` magics in the record comp9 at offsets 292, 194198, 198192, 198200; the
  validator's `198200+36 = 198236` is exactly the packed stub length, so the prefix detection works (tested, §3).
- The build needs python3 + binutils objdump (the AVX-512 confinement gate), llvm-strip-17, lld-17, llvm-profdata-17.

## 3. Test: Modal CPU rehearsal (`modal_hpja_test.py`, app `zenith-hpja-test`, env `dev-neel`, cpu=8, 48–64 GB, no GPU)

Image = the HPJA catalog image by digest (`modal.Image.from_registry("ubuntu:24.04@sha256:b3cc40b7…" | "ubuntu:22.04@sha256:58b87898…", add_python="3.11")`, selected by `HPJA_OS`,
+ the base image's extras `util-linux ca-certificates curl libarchive-tools time`). Steps mirror the harness:
`bsdtar` extract → single-top-dir check → flatten into `/entry` → `chmod u=rwX,go=rX`, `0555` scripts → `install.sh`
as root (copied alone, cwd `/`) → `groupadd/useradd 65532 contestant` → `/entry` root-owned, `a-w` (bind-mount `ro`
is refused inside Modal's gVisor; writability from UID 65532 verified impossible) → `build.sh` via `setpriv
--reuid=65532 --regid=65532 --clear-groups --inh-caps=-all --no-new-privs` with only `PATH` in the environment, cwd
`/work` (1777), under `/usr/bin/time -v` (`unshare -n` is not permitted in gVisor, so "offline" was enforced by a dead
`http_proxy`/`https_proxy` — build.sh makes no network calls anyway) → component split and comparison with the record →
the validator's `upx-overlay` prefix detection with UPX 5.1.1 → 3 MB enwik8 smoke (same recipe as `modal_big.smoke`:
enwik8[:3,177,212] cut at an article boundary, 29-line intro split + phda9/WIT encode, `cmix -c english.dic … --transformer`,
`-d`, restore, byte compare) run **in parallel with the record comp9** so both streams are produced on the same host.

### Run 1 — ubuntu-24.04, Ubuntu's own clang-17 (before the apt pin) — 16:25–17:00 ET
install 24 s; build **rc 0**, 16:07 wall (user 983 s), **peak RSS 6.03 GB** (< 16 GiB container limit); all three
portability gates passed (AVX-512 confinement 1090 instr. in the 25 qmat_*_avx512 sections / 0 outside; no RCPPS).
Output `/work/cmix` **3,478,101 B**, sha256 `a169e3250ad4b7baabc3fdbef950fd2607da0798edcff6def753e76895ac4584`.

### Run 2 — ubuntu-24.04, apt.llvm.org clang-17 `1:17.0.6~++20240501091250+6009708b4367` (the shipped install.sh) — 17:05–17:45 ET
install 29 s; build rc 0, 15:45 wall, peak RSS 6.03 GB; **bit-identical to run 1** (`a169e325…`, 3,478,101 B).
So on noble the compiler build (Ubuntu vs upstream packaging) does not matter; the output is deterministic.

Component comparison (both runs) vs the record:

| component | record | produced (noble) | match |
|---|---|---|---|
| UPX stub (`cmix_orig`) | 198,236 B `0c921ce9…` | 199,200 B `0deecb5a…` | **no (+964 B)** |
| comp_dict | 100,866 B | 100,866 B `f519c6f0…` | yes |
| comp_order | 199,980 B | 199,980 B `6acc5dfa…` | yes |
| tfweights | 2,978,039 B | 2,978,039 B `948847d9…` | yes |
| header | 16 B | 16 B `b14cff44…` | yes |
| total | 3,477,137 B | 3,478,101 B | **no (+964 B)** |

Why: the unpacked stubs are 502,440 B (record) vs 516,184 B (noble): `.text` starts at 0xf9f0 vs 0xf650 and
`.data.rel.ro` at 0x7b0c0 vs 0x7e6a0, i.e. ≈ +14 KB of code, which LZMA-UPX compresses to +964 B. PGO is deterministic
(identical output across two independent noble builds) and the UPX version is identical, so the delta is the
**qualification userspace**: the record was built on Modal's `debian_slim` (bookworm: libstdc++-12 headers,
glibc 2.36) while noble supplies libstdc++-13 headers (`13.3.0-6ubuntu2~24.04.1`) and glibc 2.39 crt objects — the
inlined STL code differs. Same `NEEDED` set (libstdc++.so.6, libm, libgcc_s, libc), PIE.

`upx-overlay` validation: the harness logic selects prefix end 199,200 (produced) / 198,236 (record) = exactly the
stub lengths; `upx --test` and `upx -d` succeed with the pinned 5.1.1.

Smoke (3,177,212 B enwik8 prefix, sha256 `3f57418e…6f23`; host without AVX-512, so the AVX2 kernels ran):
produced compressor → **392,251 B**, stream sha256 `bca832b6ba311aea37ec305d81dfb36f8d84f7a5287943845aac5751a6aa0595`,
decode byte-exact; record comp9 on the same host → **392,251 B, identical stream sha256**, decode byte-exact; the
record's own smoke (`lex_smoke3mb_lexth11c.json`, AVX-512 host) also gave 392,251 B. Compress 557–568 s, decompress
530–548 s per 3 MB, peak RSS 6.05 GB. **The rebuilt compressor is semantically identical to the record; only the
packed stub bytes differ.**

### Run 3 — ubuntu-22.04 (jammy: apt.llvm.org clang-17 `~++20231209124227+6009708b4367`, libstdc++-12-dev 12.3.0, glibc 2.35) — the shipped configuration

## 4. Score impact and the QUALIFICATION_OS choice

With the record archive9 (95,836,613 B) and the 12-byte argument file: S(record comp9) = 99,313,762; S(noble rebuild)
= 3,478,101 + 95,836,613 + 12 = **99,314,726** if the archive were unchanged — but the archive produced by the rebuilt
compressor embeds the rebuilt stub too (`archive9 = decomp_binary(upxed) + comp_dict + tf_weights + cmix_output`,
`runner.cpp:1117`), so under HPJA the noble rebuild would be charged **≈ 2 × 964 = +1,928 B → S ≈ 99,315,690**
(estimate: the generated archive was not produced — that is the 55 h enwik9 run). Byte-identity with the record
therefore matters for S, not only for tidiness.

**Choice: `QUALIFICATION_OS=ubuntu-22.04`** (set in `entry.env`). It reproduces the record's compressor size exactly
(so the harness's rebuilt comp9 and the archive it generates are expected to have the record's sizes: S = 3,477,137 +
95,836,613 + 12 = **99,313,762**), whereas ubuntu-24.04 costs ≈ 1.9 KB. The earlier note preferring 24.04 because of its
`upx-ucl 4.2.2` is moot: install.sh installs the exact UPX 5.1.1 the record used (and the harness validates with the same
release). To get true byte-identity one would rebuild the record itself on ubuntu-22.04 (≈ 25 min CPU) and re-run the 55 h
enwik9 compression with that binary — since the stream is bit-identical, the resulting archive9 would differ from the
present one only in its embedded 198,236-byte stub; worth doing only if the committee insists on hash-identity rather
than on the harness's own rebuild. The 3 MB smoke does not exercise the real `-e enwik9` path (article reordering,
`OpenSelf("cmix")`), which is validated by the artifact package's full run; the harness will run it anyway.
